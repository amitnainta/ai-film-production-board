Help & production guide

Everything you need to run the production board on your own computer: starting and stopping it, entering API keys, and taking a short animated film from script to final cut.

01Quick start

Open PowerShell, go to the project folder, and run one command.

Go to the project folder
cd C:\Users\amitn\MyAIprojects\ai-film-production-board
Start the board (opens your browser)
.\start.ps1

The board opens at http://localhost:5070. Everything you type is saved automatically to the data folder on this computer.

Render queued shots (asks before spending)
.\render.ps1
Build the rough cut video
.\render.ps1 -Assemble
Stop everything
.\stop.ps1
First time here?

Work through One-time setup and API keys first. The board itself works without any keys; keys are only needed for automated rendering and the Claude buttons.

02How it fits together

Three pieces, all on your computer.

browserThe boardScript, cast, shot list, media, rough cut, budget and pipeline settings.
start.ps1 · port 5070Board serverServes the board, saves every change to data\, and handles uploads and the Claude buttons.
render.ps1Render workerReads queued shots, calls Kling and ElevenLabs, and writes keyframes, takes and voice files back to the board.
render.ps1 -AssembleAssemblyUses ffmpeg to build the rough-cut video plus edit files for DaVinci Resolve.

The production pipeline the board is organised around:

script→cast bible→shot list→keyframes→video takes→voices / lip-sync→rough cut→final edit

Each stage can be manual (you make the image, video or audio in the tool's own website and upload it to the board) or, for keyframes, video and voices, automated (the render worker makes it for you through the tool's API).

Local and online boards are separate

This local board started as a copy of the online board on claude.ai. They don't sync: changes made here stay here. Pick one to work in.

03One-time setup

Already done on this computer. Use this section if you set the project up somewhere else.

  1. Install the tools Node.js 20 or newer (from nodejs.org), Git, and ffmpeg. ffmpeg is only needed to build the rough-cut video.
    Install ffmpeg
    winget install Gyan.FFmpeg
  2. Get the code 
    git clone https://github.com/amitnainta/ai-film-production-board.git
  3. Create your pipeline config .\start.ps1 and .\render.ps1 create config\pipeline.json from config\pipeline.example.json automatically if it's missing. Edit it as described in API keys & voice IDs and pipeline.json reference. This file is ignored by Git, so your settings never get committed.
  4. Start the board once The first .\start.ps1 installs the board server's one dependency (the Anthropic SDK, used by the Claude buttons). That takes a few seconds and only happens once.
  5. Check everything 
    node worker/src/cli.js doctor --board data/board
    It lists anything missing: keys, model ids, voice ids, prices. Run it again after each fix until it says All set.
PowerShell says scripts are disabled?

Allow local scripts for your user account once, then open a new PowerShell window:

Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

04API keys & voice IDs

Keys live in Windows environment variables on this computer only. They are never typed into the board and never stored in the repo.

VariableNeeded forWhere to get it
KLING_ACCESS_KEYAutomated keyframes and video with KlingKling AI developer / API console → API keys (an Access Key and Secret Key pair)
KLING_SECRET_KEYSame as aboveShown with the access key when you create it. Copy it then; it may not be shown again.
ELEVENLABS_API_KEYAutomated dialogue voicesElevenLabs → your profile / developer settings → API keys
ANTHROPIC_API_KEYThe Break into shots with Claude and Suggest prompts with Claude buttonsconsole.anthropic.com → API keys

Set a key

Run one line per key in PowerShell, with your real value in the quotes:

setx KLING_ACCESS_KEY "paste-access-key-here"
setx KLING_SECRET_KEY "paste-secret-key-here"
setx ELEVENLABS_API_KEY "paste-elevenlabs-key-here"
setx ANTHROPIC_API_KEY "paste-anthropic-key-here"
Open a new PowerShell window afterwards

setx only affects windows opened after it runs. If the board server is already running, restart it so it sees the new keys: .\stop.ps1 -Server then .\start.ps1, both from the new window.

Check which keys are set

"KLING_ACCESS_KEY","KLING_SECRET_KEY","ELEVENLABS_API_KEY","ANTHROPIC_API_KEY" | % { "{0,-20} {1}" -f $_, $(if ([Environment]::GetEnvironmentVariable($_, "User")) { "set" } else { "missing" }) }

It prints only “set” or “missing”, never the key itself.

Change or remove a key

Run setx again with the new value. To remove one, delete it from Windows Settings → System → About → Advanced system settings → Environment Variables (under “User variables”).

Character voice IDs (ElevenLabs)

Each speaking character needs an ElevenLabs voice. Create or pick the voice in ElevenLabs, copy its voice ID (in the voice's details or menu), and put it in config\pipeline.json under stages.voice.voices, keyed by the character's name exactly as it appears on the board:

"voices": {
  "Arun": "21m00Tcm4TlvDq8ikWAM",
  "Grandpa": "another-voice-id"
}

The worker speaks each line with the voice of the first character listed in the shot's Characters field. Characters with no voice id fail that job with a clear error.

Kling model names

In config\pipeline.json, check stages.keyframes.model, stages.keyframes.referenceModel and stages.video.model against the model ids listed in your Kling API console, and check the baseUrl matches your account's region. See the reference.

Keep keys private

Never paste a key into the board, a shot note, a script or a chat message. If a key leaks, revoke it in that provider's console and create a new one.

05Starting & stopping

Run these from the project folder in PowerShell.

CommandWhat it does
.\start.ps1Starts the board server in the background and opens the board in your browser. If it's already running, it just opens the browser.
.\start.ps1 -NoBrowserStarts without opening a browser tab.
.\start.ps1 -Port 5071Uses another port, if 5070 is taken.
.\stop.ps1Stops the board server and any running render or assembly.
.\stop.ps1 -ServerStops only the board server.
.\stop.ps1 -WorkerStops only a running render or assembly (including any ffmpeg it started).

Logs

Background processes write their output to the renders folder:

renders\server.log, server.err.logBoard server
renders\worker.log, worker.err.logRender or assembly
Watch a render live
Get-Content renders\worker.log -Wait

Press Ctrl+C to stop watching. That doesn't stop the render.

Port

The board uses port 5070, registered in C:\Users\amitn\MyAIprojects\ports.md so it doesn't clash with your other projects. It only accepts connections from this computer.

After a restart of Windows

Nothing starts automatically. Run .\start.ps1 again; your data is all still in data\.

07Making a film, step by step

The order that works best. You can go back to any step at any time.

  1. Set up the production On Pipeline → Production settings, set the target runtime, total budget, draft and final credit rates (credits per second of video in your video tool), and the style prompt. The style prompt is added to every keyframe prompt, so it keeps the whole film's look consistent. Click Save settings.
  2. Write the script On Script & cast, paste or write the script. Screenplay format works best: scene headings (INT. ATTIC – NIGHT), action lines, then character names with their dialogue. Click Save script.
  3. Lock your cast Under Cast, add each character with a locked look: age, face, hair, build, height, outfit and any prop. Be specific and keep it short; this exact text is added to every prompt that character appears in. Add voice notes for yourself.

    Then upload up to 4 reference images per character (a character sheet or turnaround works best). The first one is the primary; automated keyframes send it to Kling to keep the face consistent. Use Make primary to change which one.

  4. Describe your locations Under Locations, add each place with its layout, props and lighting, and reference images the same way as for characters. A shot's location description is added to its keyframe prompt.
  5. Break the script into shots Click Break into shots with Claude (needs ANTHROPIC_API_KEY). After 30–90 seconds you get proposed shots with framing, duration, action, dialogue and prompts. Review them, keep Remove example shots ticked if the board still holds the example shots, then click Add to shot list. For a long script, break it down one scene at a time.

    No Claude key? Add shots yourself with + Add shot on the Shot list.

  6. Refine each shot Click a shot to open the editor. Fill in or adjust:
    • Scene / Shot numbers set the order (shown as SC01 · SH02).
    • Framing: WS (wide), MS (medium), MCU (medium close-up), CU (close-up), ECU (extreme close-up), OTS (over the shoulder), POV, INSERT.
    • Duration in seconds, Tool (video tool for this shot) and Status.
    • Characters: names separated by commas, exactly as in the cast (e.g. Arun, Tock). The first one is the speaker for automated voice.
    • Location, Action and Dialogue.
    • Keyframe prompt (describes the still image) and Motion prompt (describes the movement for the video). Suggest prompts with Claude writes or improves both.
    Click Save shot.
  7. Make keyframes Manual: click Copy with cast & style next to the keyframe prompt; it copies the prompt plus the characters' locked looks, the location description and the style prompt. Paste it into your image tool (e.g. Midjourney), pick the best image, and click Upload image under Keyframe in the shot editor.

    Automated: see Automated rendering. Queue + Keyframe in the shot editor.

  8. Make video takes Do cheap draft takes first to check motion and timing, then a final take once the shot works.

    Manual: copy the motion prompt, generate image-to-video from the keyframe in your video tool, then Upload video under Takes. Log the credits it cost with + Draft or + Final on the shot list row (it uses the credit rates from settings).

    Automated: queue + Draft take or + Final take. Kling makes 5- or 10-second clips; longer shots are trimmed in the edit.

    When a shot has several takes, choose which one plays in the cut with the select button on that take. Remove bad takes with ✕.

  9. Record voices Manual: generate the line in ElevenLabs and keep the file with your edit. Automated: queue + Dialogue voice; the audio file goes into renders\ and its path shows in the shot editor. The rough-cut assembly mixes it in automatically.
  10. Review and approve Watch the Rough cut tab, note problems in each shot's Notes, redo takes, and move shots to Approved and then Final.
  11. Assemble and finish Build the rough cut and edit files, then do the final edit, colour, music and sound mix in DaVinci Resolve. See Rough cut & final edit.
Consistency tips

Keep locked looks short and concrete (“about 130 cm tall”, “oversized navy pajamas with small yellow rocket prints”). Always give characters a primary reference image. Keep the style prompt the same for the whole film. Generate a keyframe first and animate from it instead of going straight from text to video.

08Automated rendering

Let the render worker generate keyframes, video takes and dialogue through the tools' APIs.

  1. Turn on automation for a stage On Pipeline → Pipeline stages, pick a tool the worker supports and set its mode to Automated (worker):
    StageAutomatable tools
    KeyframesKling, Mock (test)
    Video takesKling 3.0, Mock (test)
    VoicesElevenLabs, Mock (test)
    Backup video, lip-sync, music, editManual only
    Mock (test) makes free placeholder files, so you can rehearse the whole flow without spending anything. Mock output is never added to the board as real media.
  2. Queue work on shots In the shot editor's Render queue, click + Keyframe, + Draft take, + Final take and/or + Dialogue voice. The buttons are greyed out until that stage is Automated. A shot needs a keyframe prompt for a keyframe, a motion prompt and a keyframe (or a queued keyframe) for video, and dialogue for a voice.
  3. Run the render 
    .\render.ps1
    It checks your setup (doctor), then prints the plan: every job, its estimated cost, and anything held back by the budget or skipped (with the reason). Type y to start. The render then runs in the background.

    Options: -Only SC01-SH02 renders just that shot (repeat for more), and -Yes skips the question.

  4. Watch results arrive The board updates by itself as soon as the render finishes. Keyframes and selected takes appear on the shots, statuses move to Keyframe / Animating, credits are added, and the queue entries clear. Follow progress with Get-Content renders\worker.log -Wait.
  5. Check failures Failed or skipped jobs stay queued and the shot editor shows Last render failed: … with the reason. Fix the problem (prompt, key, voice id…) and run .\render.ps1 again.

Extra keyframe variants (the worker makes 2 per shot by default) stay in renders\<shot>\. Only the first is attached to the shot; upload another one by hand if you prefer it.

Stopping a render

.\stop.ps1 -Worker stops the worker on your computer, but jobs already sent to Kling or ElevenLabs keep running there and may still be charged. Their results won't be downloaded.

09Rough cut & final edit

In the board

The Rough cut tab plays every shot in order: the selected take as video, otherwise the keyframe as a held still (an animatic), otherwise a slate card. Use ◀ Prev, ▶ Play, Next ▶, or click any segment of the timeline.

Build the rough-cut video and edit files

.\render.ps1 -Assemble
With a music bed under the dialogue
.\render.ps1 -Assemble -Music C:\path\to\music.mp3

Everything lands in renders\cut\:

FileWhat it is
rough-cut.mp4The whole film: takes, stills and slates, with dialogue (and music) mixed in. 1920×1080, 24 fps by default.
timeline.fcpxmlTimeline for DaVinci Resolve: File → Import → Timeline.
timeline.edlEdit decision list for other editors.
captions.srtSubtitles from the dialogue.
timeline.json, assemble.shThe timeline data, and a script to rebuild the video by hand.

Then finish in DaVinci Resolve (or Premiere): trim, colour match, add music and effects, mix sound and export.

10Budget & cost safety

  • Plan vs. spent (Budget tab) compares what you planned per tool with what you've logged.
  • Log a purchase every time you pay for a plan or top-up: date, tool, item, amount, and credits added (video tool only). That keeps the spend gauge and the credit balance right. Provider charges go to your accounts with them, not through the board.
  • Draft vs. final rates (Pipeline → Production settings) are the credits per second your video tool charges. Logged and rendered takes use them to count credits.

How the render worker protects your budget

  • It always shows the plan and estimated cost first, and asks before any paid job runs.
  • It holds back jobs that would push projected spend past your total budget minus a safety margin (stopAtRemainingUsd, $10 by default). Held jobs are listed as HELD in the plan.
  • Estimates come from the prices in config\pipeline.json (usdPerImage, usdPerCredit, usdPerLine). If a price is 0, that stage counts as free and isn't protected, and doctor warns you. Set real prices.
  • Rehearse with Mock (test) before the first paid run.

data\ and renders\ aren't in Git, so back them up yourself. Stop the board first, then copy both folders somewhere safe, such as OneDrive or an external drive:

.\stop.ps1; Copy-Item data, renders -Destination "D:\Backups\tock-$(Get-Date -Format yyyy-MM-dd)" -Recurse

To restore, stop the board and copy the folders back. Use Export board (JSON) on the Pipeline tab for a single-file snapshot of the board's data (no media files).

13Troubleshooting

The browser says it can't reach localhost:5070
The board isn't running. Run .\start.ps1. If it still fails, read renders\server.err.log.
“Port 5070 is already in use”
Another program is using it. Run .\start.ps1 -Port 5071, or find the program with Get-NetTCPConnection -LocalPort 5070.
The header says “Connection lost. Reload to reconnect.”
The board server stopped. Run .\start.ps1, then reload the page. Nothing you saved is lost.
The Claude buttons are missing
ANTHROPIC_API_KEY isn't set, or the server was started before you set it. Set it, open a new PowerShell window, then .\stop.ps1 -Server and .\start.ps1.
“Something went wrong reaching Claude”
Check the key is valid and has credit at console.anthropic.com. The exact error is in renders\server.err.log.
The render queue buttons are greyed out
That stage is still Manual. Set it to Automated (worker) on the Pipeline tab, with a supported tool.
.\render.ps1 says “Nothing queued”
No shot has queued work, or every queued stage is manual. Queue work in the shot editor first.
Doctor says “environment variable … is not set”
Set the key with setx (see API keys) and run the command from a new PowerShell window.
“voice id for … is a placeholder” / “No ElevenLabs voice id”
Add that character's voice ID under stages.voice.voices in config\pipeline.json, spelled exactly as on the board.
“Shot has no keyframe to animate” / “no motion prompt” / “no dialogue”
Add the missing keyframe, prompt or dialogue to the shot, or queue a keyframe together with the video.
A job shows HELD in the plan
It would go over budget. Raise the budget (Pipeline → Production settings, or budget in pipeline.json), or render fewer shots with -Only.
“ffmpeg not found” when assembling
Install it with winget install Gyan.FFmpeg and open a new PowerShell window.
“A render is already running”
Wait for it to finish (watch renders\worker.log), or stop it with .\stop.ps1 -Worker.
A video won't play or seek in the board
Upload MP4 (H.264) or WebM files. Other formats may not play in the browser.
PowerShell says running scripts is disabled
Run Set-ExecutionPolicy -Scope CurrentUser RemoteSigned once, then open a new window.
